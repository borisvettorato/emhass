Use the buttons below for the electrical load forecast. Three methods are available on the Configuration page (load_forecast_method): 'typical' (default - a statistics-based profile built from a year of history, grouped by day-of-week and month), 'naive' (persistence - tomorrow is assumed to look like a recent past period), and 'mlforecaster' (a regression model using auto-regressive lags as features, needing its own fit before use). 'Load forecast calibration' scores all three methods against your own recent history with a day-ahead walk-forward comparison to help you pick the best one - reporting only, it changes nothing. 'ML forecast model fit/predict/tune' train, run and hyperparameter-tune the mlforecaster method specifically - only relevant when load_forecast_method is set to mlforecaster. 'Preview load forecast (P50/P90)' shows the forecast at bias=0 (the plain point forecast) and bias=1 (a conservative high estimate, built by reconciling a historically-informed daily total back down to each timestep) side by side, to validate load_forecast_quantile_bias against your own data before setting it for real - like the PV preview below, this changes nothing.



Use the buttons below to fit, tune and predict whichever heat pump thermal model(s) you've enabled (Heat Pump section on the Configuration page): heating-need physics model, hybrid heat pump electric/gas model, and/or self-learning-physics. Each button runs only the model(s) you've turned on and skips the rest. Only self-learning-physics can affect live dispatch, and only for rooms with 'Self-learning only' turned on (Rooms tab); the other two are informational-only forecasts. Tuning searches self-learning-physics' forgetting_factor/ridge automatically - the other two models have no tunable hyperparameters yet.



Use the buttons below for the PV forecast, which layers several optional refinements on top of your base weather-service forecast (Configuration page): a learned shading/horizon profile (per-compass-direction elevation and light transmittance, split by season, with optional per-panel or shared-inverter-group detail for chimneys, trees or multi-MPPT installations that only shade part of the array), an Open-Meteo ensemble-derived P10 estimate (each candidate weather model is scored on its own P10/P50/P90 accuracy over time, not just its average forecast), and a machine-learning adjustment layer that corrects the forecast against your own production history. 'Fit PV shading/horizon model' (re)learns the shading profile from your actual production - only relevant when 'Learn a PV shading/horizon profile' is enabled. 'Preview PV forecast' shows the current PV forecast without running a full optimization or changing anything. 'Refit PV forecast adjustment model' forces an immediate refit of the adjustment layer instead of waiting for it to age out. Only the first and third buttons change what future forecasts look like - the preview never does.
